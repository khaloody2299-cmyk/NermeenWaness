# الدرس التاسع عشر: الحماية، الجلسات، ونظام إدارة الصلاحيات

## 1. تصميم هيكل واجهة الدخول وتأمين الإرسال باستخدام `POST`
نموذج تسجيل الدخول هو البوابة الأولى للنظام، ويجب أن يتم بناؤه بطريقة لا تعرض بيانات المستخدم للخطر.
- **تحديد الوسيلة الآمنة:** يجب أن تكون الخاصية `method="POST"` في وسم الـ `<form>`. لا يجب مطلقاً استخدام `GET` لإرسال كلمات المرور لأنها ستظهر عارية في رابط المتصفح (URL) ويتم تخزينها في سجلات الشبكة.

## 2. فحص حالة إرسال البيانات وضغط زر الدخول عبر المتغير الفائق `$_SERVER`
تُعد من الممارسات الأمنية التحقق من الطريقة التي تمت بها زيارة صفحة المعالجة. يجب التأكد من أن المستخدم وصل إلى الصفحة عن طريق إرسال نموذج فعلياً وليس عبر كتابة الرابط مباشرة.

```php
<?php
// هل تم إرسال طلب (POST) فعلياً للنظام؟
if ($_SERVER["REQUEST_METHOD"] == "POST") {
    // التقاط بيانات اسم المستخدم وكلمة المرور
    $username = mysqli_real_escape_string($conn, $_POST['username']);
    $password = $_POST['password'];
}
?>
```

## 3. مطابقة بيانات الاعتماد باستخدام `SELECT` وتشفير كلمات المرور (`password_hash` و `password_verify`)
لا يجب أبداً تخزين كلمات المرور بصيغتها المقروءة في قاعدة البيانات. 
- **عند التسجيل (إنشاء الحساب):** يتم تشفير كلمة المرور العادية بتحويلها إلى سلسلة معقدة (Hash) عبر دالة `password_hash()`.
- **عند تسجيل الدخول:** يتم جلب الـ (Hash) من قاعدة البيانات بناءً على اسم المستخدم، ثم مطابقة كلمة المرور المدخلة معه باستخدام `password_verify()`.

```php
<?php
// استخراج الـ Hash الخاص بالمستخدم من قاعدة البيانات
$query = "SELECT * FROM users WHERE username = '$username'";
$result = mysqli_query($conn, $query);

if (mysqli_num_rows($result) > 0) {
    $user_record = mysqli_fetch_assoc($result);
    $hashed_password_in_db = $user_record['password']; // هذه القيمة مشفرة

    // فحص التطابق بصورة آمنة
    if (password_verify($password, $hashed_password_in_db)) {
        echo "كلمة المرور صحيحة!";
    } else {
        echo "كلمة المرور غير مطابقة.";
    }
} else {
    echo "اسم المستخدم غير مسجل.";
}
?>
```

## 4. تأمين الصفحات الداخلية المحمية بفحص الجلسات `$_SESSION` وإدارتها
لغات الويب بطبيعتها (Stateless)، أي لا تحتفظ بالهوية. لتذكر أن هذا الطالب مسجل الدخول أثناء تنقله بين صفحات المنصة، نستخدم `$_SESSION`.
- يجب استدعاء الدالة `session_start();` في أول سطر برمجي في كافة الصفحات المحمية وقبل أي أمر طباعة.

```php
<?php
session_start();

// التحقق مما إذا كانت الجلسة مسجلة مسبقاً
if (!isset($_SESSION['user_id'])) {
    // إذا كان مجهول الهوية، يتم طرده فوراً لصفحة الدخول
    header("Location: login.php");
    exit();
}

// عرض محتوى حصري للمسجلين
echo "مرحباً بك في صفحة المقررات الخاصة.";
?>
```

## 5. حماية النظام بناءً على الصلاحيات والأدوار (RBAC - Role Based Access Control)
في الأنظمة التعليمية، يوجد مدير (Admin)، أستاذ (Teacher)، وطالب (Student). يتم إدارة هذه المسميات عبر عامود في قاعدة البيانات (مثل `Role`). بعد تسجيل الدخول وتخزين قيمة `Role` داخل `$_SESSION`، يتم فحصها لإظهار أو حجب أجزاء من الواجهة (مثل إخفاء زر "حذف الطالب" إلا إذا كان المستخدم إدارياً).

```php
<?php
if ($_SESSION['user_role'] === 'Admin') {
    echo '<button>إدارة الصلاحيات وحذف السجلات</button>';
}
?>
```

## 6. تدمير فترات الجلسة بالكامل (سكربت تسجيل الخروج - Logout)
لحماية حساب المستخدم عند الانتهاء من عمله، يجب برمجة زر يوجهه لصفحة إنهاء الجلسة التي تقوم بمحو الذاكرة التخزينية المخصصة لمتصفحه.

```php
<?php
session_start(); // استدعاء الجلسة الحالية
session_unset(); // إفراغ محتويات المتغيرات
session_destroy(); // تدمير الجلسة بالكامل

// توجيه المتصفح للصفحة الرئيسية
header("Location: index.php");
exit();
?>
```
